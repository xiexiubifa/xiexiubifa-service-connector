# 邪修笔法 · 写材料（通用技能）

运行环境：需要 Python 3.8 或更高版本（只用标准库）和能访问邪修笔法写作服务的网络；不需要浏览器插件或专用浏览器。服务的上线状态见 service.json（status 为 not_deployed 时服务还没有上线，脚本连不上）。支持 MCP 的 AI 助手也可以直接连接同一个服务（见文末）。

用户的邪修笔法账号可以连接到这个 AI 助手：写作需求发给邪修笔法的写作服务，网站按自己的流程写（理解需求 → 基础设定 → 六模块提示词 → 文章），把成稿原文返回，同时存进用户网站账号的成稿记录。会员、额度都按网站的规则，由网站服务器核对。

运行：`python3 scripts/xiexiubifa.py <命令>`（Windows 上一般是 `python` 或 `py -3`；不在本技能目录时用脚本的完整路径）。每个命令在标准输出打印一个 JSON；其中 `message` 是给用户看的说明，可以照着转告；进度在标准错误里以“·”开头。

## 什么时候用

- 用户装这个技能就是为了用邪修笔法写材料。日常的写作请求——“帮我写一份……”“直接帮我写”“你直接写吧”——是让你动手写这份材料，照常交给邪修笔法写（`write`）。
- 用户明确表示这次不用邪修笔法（不用这个网站或服务），按用户的选择来；那样写出来的稿子不是邪修笔法网站写的，交付时如实说明。

## 费用和服务，先说清楚

第一次替用户用邪修笔法写之前（以及用户看起来不清楚的时候），用一两句话告诉用户：这篇交给邪修笔法网站写，和在网站上写一样，按网站会员规则使用他账号的额度；连接本身免费，付款只能由用户本人在网站会员中心完成。结果里也会写明用的是哪个账号（手机号前三位和后四位）。

## 第一次使用：连接账号

用户第一次写的时候，`write` 会返回 `needs_connection`，请求先保存在这台电脑上，**还没有发出去**。把 `message` 转告用户，链接（`connect.url`）给成可点开的形式：

1. 在平时用的浏览器里打开链接（已经登录过邪修笔法网站的话，直接看到授权页面）；
2. 没登录就先用手机号登录网站。授权页面会显示要连接的账号：浏览器里现在登录的账号就是会被连接的账号；登录的是别的账号时，在页面上点「换一个账号」；
3. 核对授权码（`connect.code`）和对话里的一致，看完页面上的说明——会发送哪些内容、保存多久、费用——再决定点「允许连接」还是「不允许」。

用户说好了，执行 `continue`：连接完成后会接着发送刚才的请求，用户不用再说一遍。用户点了「不允许」或者授权码过期，结果会说明；保存的请求可以用 `connect` 重新连接后继续，或用 `cancel --pending` 删除。

连接只需要一次，之后在后台使用；用户随时可以在网站「会员中心 → 已连接的 AI 助手」断开，或者执行 `disconnect`。

## 写一篇

```
python3 scripts/xiexiubifa.py write --request "用户的写作需求"
```

- `--request` 尽量保留用户的原话（可以整理成一段），不添加用户没给的事实、数据、单位名称。
- 用户提供的素材：`--material-file 文件`（.docx / .txt / .md，可多次）或 `--material "文字"`。PDF、图片先提取成文字。
- 用户说明了的才加：`--title`、`--words 1500`、`--level 区县级`、`--audience`、`--purpose`、`--speaker`、`--doc-type 文种编号`（见 `types`）、`--quick`（网站的「传统方式一键生成文章」）、`--deep`（网站的「深度思考」，会用掉更多额度）。
- 每个写作、改稿、润色请求在发出前都有自己的请求编号，保存在这台电脑上，直到写作服务给出答复。

按结果的 `status` 处理：

| status | 意思 | 接下来 |
| --- | --- | --- |
| `done` | 网站写好了 | 交付 `draft.text`（见“交付稿件”），附上 `draft.source`。带 `request_reused: true` 时，这是之前已经交给网站的同一个请求，没有重复写 |
| `running` | 网站还在写（一般要几分钟） | 告诉用户正在写，执行 `result --job <job_id>`，直到不是 `running` |
| `needs_connection` | 还没连接账号，或者连接已经失效（过期、在网站上断开） | 见上一节。连接失效时 `message` 会写明之前连接的账号；用同一个手机号重新连接，任务才能接着做 |
| `outcome_unknown` | 请求已经发出，但没有收到回复（网络中断、超时），不确定网站有没有开始写 | 转告 `message`。稍后执行 `continue`：用同一个请求编号再问一次，网站已经开始或写完的会直接取回，不会重复写、不会重复使用额度 |
| `account_changed` | 结果还不确定的请求是用另一个账号发的，现在连接的是别的账号 | 转告 `message`，让用户选：用原来的账号重新连接后 `continue` 取回；或 `continue --resend` 在现在的账号下重新写（会用这个账号的额度）；或 `cancel --pending` 放弃 |
| `pending_unresolved` | 还有一个结果不确定的请求 | 先执行 `continue` 确认它，或在用户同意后 `cancel --pending`，再发新的请求 |
| `needs_membership` | 网站提示要开通会员、体验结束或额度用完 | 转告 `message`（里面有网站的原话、账号和会员中心链接）。会员中心在用户平时用的浏览器里打开；打开后先确认登录的是同一个账号（手机号前三位和后四位一致），付款由用户本人在网站上完成。用户说开通好了，执行 `continue --job <job_id>`：从停下的那一步接着写，已完成的步骤不会重复扣额度 |
| `needs_more_info` | 网站要先补充设定（如标题） | 问用户 `missing` 里的项，然后 `continue --job <job_id> --title "…"` 等 |
| `needs_login` | 网站不再确认这个账号的登录 | 转告 `message`；用同一个手机号重新连接（`connect`）后 `continue --job <job_id>` |
| `temporarily_failed` | 网站暂时没完成 | 转告原因；稍后 `continue --job <job_id>` 再试 |
| `cleared` | 这个任务已经结束、过了保留期限或已删除 | 转告 `message`，成稿在网站的成稿记录里（`records`） |
| `account_disabled` | 网站停用了这个账号 | 转告 `message`，需要联系网站；开通会员解决不了 |
| `unavailable` / `busy` | 连不上写作服务、服务没有回应，或请求太多 | 转告 `message`：它会说请求有没有发出、保存在哪里；服务还没上线时也会如实说明 |
| `failed` / `error` | 其他问题 | 转告 `message` |

结果里没有 `draft` 时，就是还没有稿件，`message` 会说明原因和网站的下一步。

## 交付稿件

- 把 `draft.text` 原样交给用户，连同 `draft.source`（例如“来源：邪修笔法（xiexiubifa.cn）成稿记录 … 第 1 稿”）。要提醒的事（比如稿中有几处“待补充”）另起一段说，正文保持原样。
- 用户要改：`revise --record <record_id> --instruction "用户的修改意见"`，网站生成新的一稿，原稿保留。要润色：`polish --file 原稿.txt`（返回两个版本）。
- 如果你按用户的要求自己动手改了内容，就说明这是改过的版本，不再标为网站原稿。
- 要 Word：`word --record <record_id> [--version N] [--out 文件]`，保存网站版式的 .docx（默认在当前目录的 `xiexiubifa-output/`）。需要先连接时，第几稿和保存位置会一起保存，连接后 `continue` 照样存到那里。

## 用户的选择

- 用户想用别的方式写，按用户的选择来（见“什么时候用”）。
- 用户不想继续某个任务：`cancel --job <job_id>`；连同保存的需求和素材一起删除：加 `--delete-input`。
- 删除保存在这台电脑上的请求：`cancel --pending`（结果不确定的请求删除后，网站那边可能仍会写完，结果会如实说明）。
- 用户想断开：`disconnect`（也可以在网站会员中心断开）。保存在这台电脑上的请求不会因此删除。

## 费用和数据

- 连接免费；写作、改稿、润色和在网站上写一样，按网站会员规则使用用户账号的额度。按网站现在的规则，新手机号第一次登录有 24 小时免费体验（额度有限），之后需要在网站会员中心开通会员；规则和价格以网站会员中心为准。
- 发送的内容：写作需求、用户给的素材、改稿和润色的文字。成稿存在用户网站账号的成稿记录里；写作任务在服务端保留 7 天（等待开通会员或补充信息的保留 30 天）；任务删除或到期后，请求编号对应的任务编号和成稿记录编号再保留 30 天（不含需求和素材），用来避免同一个请求被重复写。
- 用户问起时，执行 `info`（服务说明）或 `account`（会员等级和剩余额度）。

## 其他命令

| 命令 | 作用 |
| --- | --- |
| `result --job ID [--wait 20]` | 查看进度和结果（只读取，不扣额度） |
| `continue [--job ID] [--resend]` | 连接好之后发送保存的请求；没收到回复之后用同一个编号确认；开通会员、补充信息或暂时失败之后接着写 |
| `drafts` / `draft --record ID [--version N]` | 网站上的成稿记录 / 读取一篇 |
| `word --record ID [--version N] [--out 文件]` | 网站版式的 Word |
| `types [--doc-type 编号]` | 文种目录 |
| `account` / `info` / `doctor` | 账号与额度 / 服务说明 / 检查环境、连接和服务的上线状态 |
| `connect [--open]` / `disconnect` | 连接 / 断开 |
| `cancel --job ID [--delete-input]` / `cancel --pending` | 取消任务 / 删除这台电脑上保存的请求 |

连接凭据保存在用户目录下只有本人可读的文件里（`doctor` 显示位置），不会打印到输出里。

## 支持 MCP 的 AI 助手

如果 AI 助手已经连接了邪修笔法写作服务的 MCP 端点（能看到 `write_material`、`get_writing_result`、`continue_writing` 等工具），可以直接用这些工具，效果相同；连接时由助手自己的 OAuth 流程在浏览器里打开同一个授权页面。调用 `write_material`、`revise_draft`、`polish_text` 时可以带上 `request_id`（这次请求自己的编号），没收到结果要重试时用同一个编号，不会重复写。MCP 地址见 `service.json`。

## 出问题时

- `doctor`：Python 版本、服务能否访问、是否已连接、连接的是哪个账号、服务的上线状态、有没有保存的请求。
- 提示找不到 Python：需要安装 Python 3.8 或更高版本。
- 连不上服务：`message` 会说请求有没有发出去；没发出去的请求保存在这台电脑上，稍后执行 `continue` 即可。`service.json` 写着 `not_deployed` 时，服务还没有上线，现在连不上是预期的。
